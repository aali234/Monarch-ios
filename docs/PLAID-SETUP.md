# Plaid Sandbox and FastAPI setup

The native app and FastAPI proxy are implemented. This guide connects them to your own **free Plaid Sandbox** account. Sandbox uses test banks and generated financial data. Live bank access and production approval are separate from this setup.

## Create and verify your Plaid account

1. Open [Plaid signup](https://dashboard.plaid.com/signup) in your browser. Enter your own details and complete email verification. If onboarding asks what you are building, this project is a personal finance iOS prototype.
2. Open [API keys in Plaid Dashboard](https://dashboard.plaid.com/developers/keys). Find your `client_id` and the **Sandbox** secret.
3. Enter these values directly in the secret settings below. Keep them out of source code, issues, screenshots and chat.

Account signup and email verification require your browser. No Plaid developer account or provider credentials are created by the source code.

## Verify FastAPI on GitHub without a Mac

1. Open [the repository's Actions secrets](https://github.com/aali234/Monarch-ios/settings/secrets/actions). Add these **repository secrets**:

   | Secret name | Value |
   | --- | --- |
   | `PLAID_CLIENT_ID` | Your Plaid client ID |
   | `PLAID_SECRET` | Your Plaid **Sandbox** secret |

2. Open [FastAPI and Plaid Sandbox](https://github.com/aali234/Monarch-ios/actions/workflows/plaid-sandbox.yml). Choose **Run workflow**, keep `transactions` selected and leave `proxy_url` blank.
3. The workflow first runs the mocked-provider tests. Its manual-only live job then starts a temporary FastAPI server, authenticates to Plaid Sandbox, creates a test Item, exchanges its token, fetches accounts, waits for transaction history and checks incremental sync. Select `liabilities` or `investments` in a later run to verify those products.

The temporary app key is generated in memory. No API credentials, access tokens, financial rows or data artifacts are printed or saved by this job. The disposable test Item remains in Plaid Sandbox. Push and pull-request runs execute the mocked tests only; only a manual run makes live Sandbox calls.

The temporary server stops when the test ends. A successful manual run verifies FastAPI and the supplied credentials against Plaid; it does not exercise the iOS Link login screens.

## Host the API on Render

The root [render.yaml](../render.yaml) defines a free Python service with `rootDir: proxy`, the correct startup command, an automatically generated app key, and Sandbox controls enabled. Ship24 is optional and is not requested during Plaid deployment.

Connect Render in this chat to let the agent create and inspect the service, or open [Deploy this repository on Render](https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2Faali234%2FMonarch-ios) in your browser. The Blueprint setup prompts for `PLAID_CLIENT_ID` and `PLAID_SECRET`; use the same Sandbox values. `APP_KEY` is generated by Render. Keep `PLAID_ENV=sandbox` and `ALLOW_PRODUCTION=false`.

After deployment, copy the actual HTTPS service URL from Render. Open its `/health` path and wait for JSON showing `environment: sandbox`, `configured: true`, and `sandbox_tools: true`. The free service sleeps after 15 minutes of inactivity and takes about a minute to wake; let it wake before testing. Health reports configuration presence. An authenticated live check verifies the actual Plaid credentials.

To run that live check against the **deployed** service from GitHub:

1. In Render's Environment page, copy its generated `APP_KEY` into a repository Actions secret also named `APP_KEY`.
2. Run **FastAPI and Plaid Sandbox** with the Render HTTPS URL in `proxy_url`.
3. This mode authenticates to the hosted service and runs the same checks. It uses the Plaid keys configured on Render; it does not send repository Plaid secrets to the hosted URL.

## Connect the iOS app

In the app, tap the grid button → **Settings & connections**. Enter the Render HTTPS URL and its `APP_KEY`, then tap **Save & test connection**. The app keeps this pairing key in Keychain. The Plaid secret stays on the server.

Under **Accounts → Add an account**, use **Add Sandbox test bank instantly** for a quick data-path test. Use **Connect with Plaid → First Platypus Bank** to test the bank login UI, with `user_good` / `pass_good` and MFA code `1234` if requested. Pull to refresh while initial history is being prepared. The [full Sandbox checklist](SANDBOX-TESTING.md) covers incremental updates, reconnection and the other product screens.

The current iOS screenshot workflow uses explicit example fixtures. It runs independently of these live API tests.

## Run the same backend checks locally

With the proxy dependencies installed and the two Sandbox credentials in your environment or the ignored `proxy/.env`:

```bash
cd proxy
.venv/bin/python verify_sandbox.py --product transactions
```

This starts and stops its own loopback server on port 8765, with a temporary app key. To verify an already running local or hosted proxy, put its pairing key in `APP_KEY` and use:

```bash
.venv/bin/python sandbox_smoke.py --url https://YOUR-SERVICE.onrender.com --product transactions
```
